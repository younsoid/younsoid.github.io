                            NCDC_batch_vcf2maf_V.1.3.3_github.sh 파일을 확인해본 결과이다. 병렬 개수, 샘플 ID 길이, 입출력 폴더, vcf2maf/VEP 위치, GRCh37 FASTA 3종을 지정한다. 실패하면 다른 fasta를 사용해서 돌리는것이다. 경로에 102_GRCh37, 뒤쪽 106행에 ensembl-vep-release-102가 보이는데, 원래 작업 환경이 VEP 102였다는 뜻이다. resolve_reference_paths()가 설정한 경로에 파일이 없으면 SEARCH_ROOTS 아래를 find로 뒤져서 hg19.fa, chain 파일, homo_sapiens 폴더 등을 찾는다. 워크스테이션마다 경로가 달라도 돌아가게 하려는 장치인데, Docker 버전에서는 이걸 reference-config.json으로 대체해 "어디를 뒤질지"를 사용자가 명시하도록 바꿨다. vcf2maf.pl과 VEP가 있는지 확인하고 FASTA에 .fai가 없으면 samtools faidx로, liftover용 .dict가 없으면 Picard로 만든다. 로그 TSV의 헤더를 작성한다. (Docker에서 돌린 doctor-bundle이 이 단계에 해당) 공백과 괄호를 _ 로 바꾼 작업용 이름을 만들고 파일명 앞 8글자를 Tumor_Sample_Barcode로 쓴다. 그래서 S002-054_S002-054_...vcf는 S002-054가 된다. file 명령으로 실제 형식을 보고 gzip/bzip2/xz면 풀고, zip/7z/rar/tar면 압축을 풀어 안에서 VCF를 찾는다. zip 안에 VCF가 여러개면 첫 1개만 쓴다. 엑셀은 형식만 감지해서 플래그를 세우고 VCF처럼 실행한다. (사실상 실패를 로그에 남기는것) - GINS 형식 보정 - POS REF ALT ...처럼 ID와 QUAL 열이 빠진 특정 기관(GINS) 형식을 감지하면 awk로 빈 ID/QUAL 열을 끼워 넣어 표준 VCF로 만든다. REF가 나 .이면 N으로 바꾼다. - 줄바꿈 변환 - Windows에서 만든 파일(CRLF)이면 dos2unix로 LF로 바꾼다. - chr 접두어 제거 - 헤더에 있으면 chr1 → 1로 통일한다. 결과 MAF 염색체가 숫자 표기가 되는 이유이고, Docker config의 output_contig_style: numeric이 이걸 재현한 것이다. - 다만 조건이 contig 헤더 유무라서 헤더가 없는 ANNOVAR 파일은 이 단계를 건너뛰고 chr이 붙은 채로 넘어간다. - gVCF에서 변이만 추출 - 파일 어디에든 “GVCF”라는 글자나 가 있으면 gVCF로 보고, SNV와 indel만 남긴다. - DRAGEN 파일(S005)처럼 헤더의 명령줄에 GVCF라는 단어만 있어도 gVCF로 분류된다. - 앞선 Docker 로그에서 S005가 is_gvcf: true로 나온 것도 같은 규칙이다. 그리고 FILTER가 PASS인지는 보지 않기 때문에 S005의 weak_evidence 2만여 개가 그대로 통과한다. - Genome build 판별과 liftover - 줄의 문자열을 보고, 없으면 chr1 contig 길이로 판단하고, 그것도 없으면 기본값 GRCh37로 처리한다. - GRCh38이면 Picard LiftoverVcf로 hg19로 옮기는데, chain 파일 이름에 따라 chr을 붙이거나 떼서 맞춘 뒤(1009–1017행) 시도하고, 결과가 비면 다음 chain으로 넘어간다. - 샘플 헤더 보정 - 가명화 과정에서 줄의 샘플 열 이름이 지워진 경우를 고친다. - 헤더는 8열인데 데이터가 10열 이상이면 FORMAT과 샘플명을, 헤더가 9열(FORMAT까지)이면 샘플명만 추가한다. - 샘플을 끝내 못 찾으면 파일명 8글자를 tumor ID로 강제 사용한다. 샘플이 2개면 이름에 normal/blood/germ 등이 들어간 쪽을 normal로 추정한다. - vcf2maf 실행과 FASTA 대체 시도 - FASTA 3종을 순서대로 넣어 vcf2maf를 돌리고, 성공하면 멈츤다. 변이가 하나도 없는 VCF면 vcf2maf를 건너뛰고 헤더만 있는 빈 MAF를 만든다. - 같은 샘플 ID의 파일이 동시에 vcf2maf를 돌지 않도록 flock으로 잠금 건다. 결과는 log_line으로 남는다. - 병렬 실행 - INPUT_DIR에서 이름에 .vcf가 들어간 모든 파일을 찾아 워커로 넘긴다. -
